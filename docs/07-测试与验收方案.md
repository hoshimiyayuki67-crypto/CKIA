# 07 测试与验收方案

> 核心主张：**准确率不能靠自述，需要可验证的证据。** 通过金标测试集、场景化测试、用户试用与压力测试共同佐证。

## 一、测试指标体系

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 答案准确率 | 回答要点与金标答案一致的比例 | ≥ 85% |
| 出处正确率 | 标注来源与实际依据一致的比例 | 100% |
| 拒答正确率 | 应拒答而未答错的比例 | ≥ 95% |
| 卡片字段完整率 | 必填字段全部抽取成功的比例 | ≥ 85% |
| 截图识别成功率 | 可正确定位到对应文件的截图比例 | ≥ 80% |
| 平均响应时间 | 从提问到首屏输出的时间 | ≤ 3 秒 |
| 用户满意度 | 反馈"有用"占总反馈的比例 | ≥ 80% |

## 二、测试方法

### 1. 金标测试集

人工构建 **100 条**标准问答对，覆盖六大类事务，每周自动回归测试。

每条包含：提问、标准答案要点、正确出处。

数据格式（[tests/golden_set/sample.jsonl](../tests/golden_set/sample.jsonl)）：

```json
{"question": "助学贷款怎么申请？", "expected_points": ["生源地信用助学贷款", "学生资助管理中心"], "expected_source": "关于做好2026年生源地信用助学贷款工作的通知", "should_refuse": false}
```

运行方式：

```bash
python -m scripts.run_golden_test
```

### 2. 场景化测试

| 场景 | 测试要点 |
| --- | --- |
| 标准提问 | 规范问法能否正确回答 |
| 口语提问 | 模糊问法能否被正确理解或追问澄清 |
| 群聊截图 | 带聊天界面元素的截图能否正确解析 |
| 模糊截图 | 图片不清时能否优雅降级 |
| 过期通知 | 上传旧版通知能否提示版本差异 |
| 无关提问 | 超出知识库范围的问题能否正确拒答 |
| 冲突信息 | 官方层与经验层冲突时能否正确取舍 |

### 3. 用户试用测试

在校内招募试用用户，观察真实使用行为，收集反馈与问题聚类。

### 4. 压力测试

模拟并发访问，验证系统在高负载下的响应稳定性与降级表现。

## 三、验收标准

项目达到以下标准即视为验收通过：

1. 覆盖**不少于 15 类**高频校园事务，且每类均有可演示的完整问答流程；
2. 金标测试集**答案准确率 ≥ 85%**，**出处标注率 100%**；
3. 关键功能（智能问答、以图问图、办事卡片、主动提醒）**均可现场演示**；
4. 系统连续运行 7 天无崩溃，平均响应时间 ≤ 3 秒；
5. 完成校内试用，**试用用户 ≥ 500 人**，用户满意度 ≥ 80%；
6. 全部代码、文档、测试报告齐备，具备复现与说明能力。

## 四、测试用例组织

```
tests/
├── __init__.py
├── test_rag.py            # 拒答逻辑、查询改写等单元测试
└── golden_set/
    └── sample.jsonl       # 金标问答对（目标 100 条）
```

| 用例类型 | 位置 | 说明 |
| --- | --- | --- |
| 单元测试 | `tests/test_rag.py` | 链路关键节点，无需外部模型 |
| 金标回归 | `tests/golden_set/*.jsonl` | 每周全量回归 |
| 场景用例 | 场景化测试（人工/半自动） | 覆盖七类真实场景 |
| 压力用例 | 压测脚本（待建设） | 并发稳定性与降级 |
