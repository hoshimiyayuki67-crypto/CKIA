# 05 提示词设计

> 对应代码：[app/intelligence/prompts.py](../app/intelligence/prompts.py)。
> 核心思想：从输入侧压缩模型的自由发挥空间，让"仅依据参考资料作答"成为硬约束。

## 一、系统提示词（生成环节）

```
你是一名校园事务助手。请依据提供的「参考资料」回答学生提问。

硬性规则：
1. 只能使用参考资料中的信息，不得引入任何外部知识或自行推测；
2. 若参考资料无法回答该问题，直接回复：未查询到相关规定，建议咨询相关部门；
3. 不得编造材料名称、办理地点、办公时间、截止日期、金额等任何具体信息；
4. 参考资料中未提及的字段，填写为「未查到明确信息」；
5. 输出必须为 JSON，不得包含任何 JSON 之外的解释性文字。

输出字段：
matter_name, target_users, materials[], location, office_hours,
deadline, channel, contact, sources[], notes[], confidence

参考资料：
{context}
```

**要点**：

- 规则 1、3 抑制幻觉；
- 规则 4 保证缺失字段不被编造；
- 规则 5 配合服务端模板渲染，模型不直接控制排版；
- `{context}` 由检索片段按 `[编号] 正文` 拼装，实现出处与答案一一对应（见 [app/intelligence/llm.py](../app/intelligence/llm.py) `_compose`）。

## 二、意图识别提示词

```
判断学生提问属于哪一类校园事务，只输出类别名称。
可选类别：资助、教务、财务、学籍、就业、生活。
```

## 三、查询改写提示词

```
将口语化的校园提问改写为包含规范术语的检索查询语句，只输出改写后的语句。
```

配合人工维护的**同义词表**（见 [app/core/intent.py](../app/core/intent.py)）解决口语与规范文档之间的语义鸿沟，例如：

| 口语表述 | 规范术语 |
| --- | --- |
| 那个钱 | 资助、助学金、补助 |
| 贷款 | 生源地信用助学贷款 |
| 报账 | 费用报销 |
| 盖章 | 证明盖章 |

## 四、字段抽取校验规则

| 字段 | 校验规则 |
| --- | --- |
| deadline | 必须为合法日期，且不早于当前日期（否则提示疑似过期） |
| location | 非空，且能对应到参考资料中的原文表述 |
| materials | 至少一项，每项均为参考资料中出现的材料名称 |
| sources | 至少一条，且能对应到实际文档元数据 |
| confidence | 0–1 之间，低于 0.6 时在卡片上附加"信息可能不完整"提示 |

对应实现：[app/core/extractor.py](../app/core/extractor.py) 的 `validate`。

## 五、结构化输出的三段式约束

1. **格式约束**：提示词要求 JSON 输出（通过 `response_format=json_object` 强化）；
2. **模板渲染**：服务端用模板渲染卡片，模型不控制排版；
3. **校验重试**：结构校验失败触发一次重试，仍失败则降级为纯文本答案并标注"格式解析失败"。

## 六、兜底与降级话术

| 场景 | 话术方向 |
| --- | --- |
| 检索不到依据 | 「未查询到相关规定，建议咨询××部门。」并附咨询渠道 |
| 截图模糊 | 「图片较模糊，建议重新上传或直接描述问题。」 |
| 截图与正式文件有出入 | 「您上传的截图与现行文件可能存在出入，建议以《××》为准。」 |
| 官方层与经验层冲突 | 以官方层为准，并主动提示差异 |
| 格式解析失败 | 输出带出处的纯文本答案，不使用空洞的"服务异常，请稍后再试" |
