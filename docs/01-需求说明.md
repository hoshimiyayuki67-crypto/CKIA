# 01 需求说明

> 本文档由《校园万事通_软件创意设计文档》提炼，作为开发实现的需求依据。

## 一、项目背景

校园信息是公开的、权威文档是存在的，但它们没有被组织成「能直接回答问题并指引行动」的形态。本项目的创意来自三个反复发生的校园日常。

### 场景一：截图会沉底

班级群里辅导员转发的通知截图，两小时后被上百条闲聊刷到看不见的位置。**截图不能搜索、不能复制、过期即失效**——这是校园信息传播最真实的形态，也是最被产品设计忽视的形态。

### 场景二：白跑一趟

学生去办报销，被告知「要先去另一个窗口盖章」；盖完章回来又被告知「本周封账」。失败不是因为不努力，而是因为**没有人一次性告诉过他完整的要求**。

### 场景三：同一个问题被问一百遍

辅导员每学期要回答几十次同样的问题。**重复劳动消耗行政人员精力，学校也拿不到数据判断哪份通知写得最让人看不懂。**

### 现存方案的不足

| 现有渠道 | 学生实际体验 |
| --- | --- |
| 官网通知公告 | 需自行搜索与提炼，长文阅读成本高 |
| 班级群转发 | 以截图流转，不可检索，刷屏即沉底 |
| 询问同学 | 答案不权威，存在信息失真 |
| 询问辅导员 | 受工作时间限制，无法即时响应 |
| 直接去办公室 | 一次跑空即损失半天 |
| 通用聊天机器人 | 无校内知识、无出处、易编造，不敢信 |

## 二、项目定位

| 维度 | 定位说明 |
| --- | --- |
| 产品形态 | 微信端对话式智能体（公众号 / 企业微信接入），无独立 App |
| 核心能力 | 校园事务的检索、理解、判断与执行指引 |
| 服务对象 | 在校学生（首要）、辅导员与行政人员（次要） |
| 使用场景 | 办事前的流程确认、通知解读、临期事项提醒 |
| 输出形态 | 结构化办事卡片，而非一段聊天文字 |
| 技术底座 | 大语言模型 + 检索增强生成（RAG）+ 多模态理解 |

一句话定义：**校园万事通是一个装进微信里的校园事务智能体：学生用一句话、或者一张通知截图提问，即可获得一份可照着办的办事清单。**

## 三、四条设计原则

1. **宁可说"不知道"，绝不编造** —— 检索不到依据时明确拒答并给出咨询渠道；
2. **每个答案都能追到源头** —— 强制标注文件名、发布部门、发布日期，可一键查看原文；
3. **输出必须能直接用** —— 材料清单可勾选、地点具体到窗口、时间精确到时段、截止日期高亮；
4. **主动，而不是等待询问** —— 关键节点由系统跟着学期日历主动推送。

成功标准是「用户照着办成了」，而不是「用户看懂了」。

## 四、功能范围

覆盖 **资助、教务、财务、学籍、就业、生活** 六大类校园事务，首批实现不少于 **15 类**高频事项的智能应答。

| 类别 | 收录内容 | 主要来源部门 |
| --- | --- | --- |
| 资助类 | 助学贷款、奖助学金、困难认定、勤工助学 | 学生工作处、资助管理中心 |
| 教务类 | 选课、成绩、缓考补考、转专业、学籍异动 | 教务处、学院教学办 |
| 财务类 | 费用报销、缴费、校园卡 | 财务处 |
| 学籍类 | 学籍证明、档案、成绩单盖章 | 教务处、档案馆 |
| 就业类 | 推荐表、三方协议、档案转递、就业补贴 | 就业指导中心 |
| 生活服务类 | 宿舍、图书馆、网络、医疗、场馆预约 | 后勤处、图书馆 |

## 五、功能优先级矩阵

| 优先级 | 功能 | 理由 |
| --- | --- | --- |
| P0（必须） | 智能问答、出处标注、办事卡片 | 产品的最小可用闭环 |
| P1（重要） | 以图问图、拒答机制 | 差异化竞争力与可信度保障 |
| P2（增强） | 主动提醒、双层知识库 | 提升留存与覆盖面 |
| P3（延展） | 咨询数据分析、多校复制 | 价值延伸，依赖数据积累 |

## 六、迭代路线

| 版本 | 目标 | 核心交付 |
| --- | --- | --- |
| V0.1 原型版 | 跑通链路 | 单一事项的问答与出处标注 |
| V0.5 内测版 | 覆盖高频事项 | 15 类事务、办事卡片、拒答机制 |
| V1.0 校内版 | 全量开放 | 以图问图、主动提醒、双层知识库 |
| V1.5 数据版 | 价值延伸 | 咨询热力图、知识库自助更新后台 |
| V2.0 复制版 | 跨校推广 | 知识库导入工具、多校配置管理 |

## 七、非功能需求

| 维度 | 要求 |
| --- | --- |
| 响应时间 | 平均响应时间 ≤ 3 秒 |
| 并发承载 | ≥ 200 QPS |
| 服务可用性 | ≥ 99%，具备多模型备份与降级策略 |
| 隐私合规 | 不采集学号、姓名、身份证等任何个人信息；日志匿名化 |
| 数据合规 | 仅收录学校公开发布的规章制度与通知 |
| 内容标识 | AI 生成内容按规范作显著标识 |
