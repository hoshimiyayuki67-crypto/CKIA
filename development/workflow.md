# 开发流程

## 环境准备

目标环境：Python 3.11、Flutter 3.x、Android Studio/Android SDK、Git；Docker 为后续部署可选项。先运行 `scripts/check-environment.ps1`，再按 `backend/DEVELOPMENT.md`、`mobile/DEVELOPMENT.md` 初始化。

Python 已保存首次验证的依赖版本清单 `backend/requirements-dev.lock.txt`；Flutter 待安装验证后生成 `pubspec.lock`。后续升级需单独审阅。模型密钥仅放入本地环境变量；不要放入 Flutter 或 H5。

## 每个功能的交付顺序

1. 从 backlog 选择一个事项，写出输入、输出、拒答条件与验收例子。
2. 收集真实公开来源，登记发布部门、日期、URL、版本和有效期；人工核验后才入库。
3. 先修改 `contracts/` 和后端模型，确认缺失字段、来源与错误语义，再实现服务。
4. 后端完成后连接 Flutter/H5。材料勾选是用户本地状态，不修改官方要求。
5. 跑该功能相关测试、金标回归和端侧静态检查；涉及截图/推送时补真机验证。
6. 更新任务状态和验证证据，再提交评审。合并与发布按团队流程执行。

建议分支 `codex/<功能名>`；提交保持单一目的。提交前检查 `git diff` 和 `git status`，不要把既有删除或本地密钥意外纳入当前功能。

## 阶段与检查门槛

| 阶段 | 交付 | 必须验证 |
| --- | --- | --- |
| V0.1 | 单事项真实来源问答 | 无依据拒答、引用绑定、端到端显示 |
| V0.5 | ≥15 个事项、卡片勾选 | 字段完整率 ≥85%、金标 100 条准备完成 |
| V1.0 | 截图、提醒、双层知识 | 模糊图降级、旧版本提示、推送真机到达与去重 |
| V1.5 | 匿名分析与更新后台 | 脱敏、权限、审计、知识版本回归 |

每周运行金标集，报告答案准确率、出处正确率、拒答正确率、字段完整率及响应耗时。金标必须人工审核，不能将模型自己的输出作为正确答案。

## 发布准备

APK 构建之前验证 Android 权限、断网缓存、WebView 桥接来源限制与推送授权。生产接口使用 HTTPS，限流、角色权限、审计和备份完成后再部署。CI、签名和推送凭证在首个可运行链路完成后配置。
